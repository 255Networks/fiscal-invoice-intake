# Fiscal Invoice Intake
Malachi Pride · 255 Networks

A finance reviewer receives a mix of invoice requests, including a misspelled customer name and a repeat submission. This local Python demo turns them into three CSV queues. The release candidate contains invented records and a vendor-neutral schema.

## Run the example

From this directory with Python 3.10+:

```sh
python3 intake.py --out review-output
python3 -m unittest -v
```

Open the three generated CSVs. The sample produces **1 ready, 4 for review and 2 duplicates**. Use `--data DIRECTORY` for another fixture with the same headers. An existing output directory must be empty. The program never issues an invoice.

| Example | Result | Why |
| --- | --- | --- |
| REQ-01 | Ready | Confirmed customer key and matching name, positive amount and supported currency. |
| REQ-02 | Duplicate | Same invoice reference and canonical payload as REQ-01. |
| REQ-03 | Review | A name resembles a known customer, but the request has no authoritative customer key. |
| REQ-04 | Duplicate | A prior accepted record already contains this invoice and payload. |
| REQ-05 and REQ-06 | Review both | Same invoice reference with conflicting amounts. The batch is checked before either can enter the ready queue. |
| REQ-07 | Review | The supplied name disagrees with the customer registered under the supplied key. |

## Matching and duplicate rules

The business key is issuer plus invoice reference. The canonical payload is customer key, currency and amount in minor units. A different request ID cannot make the same invoice new. An accepted prior record with a changed payload goes to review. A normalized exact name confirms the supplied key. An approximate name is a suggestion for human review only.

This is a preparation model for a reviewed export. Customer IDs are fictional. The schema omits government identifiers and jurisdiction-specific tax fields. Ready means eligible for review in this demo. The prior-accepted file is a read-only fixture; a downstream reviewer owns any later acceptance and history update.

## Files

- `data/customers.csv` identifies the fictional customers.
- `data/requests.csv` is the incoming batch.
- `data/prior.csv` lists a previously accepted invoice signature.
- `sample-output/` contains the exact three CSVs generated by the included batch.
